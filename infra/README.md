# infra

Terraform for the AWS side of Agent Phish Guard. Everything here is least privilege, and everything is destroyed when the hackathon ends.

## What it creates

| Resource | Purpose |
| --- | --- |
| `agent-phish-guard-bedrock-invoke` policy | Invoke only the Claude models the agent uses (`bedrock_inference_profiles`), and only through their cross-region inference profiles. Terraform reads each profile from AWS to get the exact regional model ARNs behind it, so there are no wildcards. |
| `agent-phish-guard-agent` role and instance profile | For the compute that runs the agent (EC2 by default, see `agent_trusted_services`; launch the instance with the `agent-phish-guard-agent` instance profile). Its only permission is the invoke policy. |
| `phishguard-developers` group, users `ale` and `hannah` | Teammates calling Bedrock from their laptops: the invoke policy, read-only model listing, managing their own password and MFA, and `aws login` (AWS's `SignInLocalDevelopmentAccess` policy, which turns a console session into CLI credentials). No access keys. |
| `agent-phish-guard-monthly` budget | Email alerts early, because the free-plan credits are only $100: when actual spend passes $5, $10, $25 and $50, and when the month's forecast passes $80 (AWS allows five alerts per budget). Credits are excluded so the budget tracks real usage. Billing data updates a few times a day, so an alert can lag by several hours. Created only if `budget_email` is set. |
| State bucket (`bootstrap/`) | S3 bucket for the Terraform state: versioned, encrypted, public access blocked, HTTPS only, with S3 native locking. The state never lives in the repo. |

Not managed here: the `stephy` admin user and the `phishguard-admins` group, created by hand to run Terraform.

**Cost:** IAM and the first two budgets are free. The state bucket holds a few KB.

## Apply

Sign in as an admin (`aws login --profile phishguard --region us-east-1`), then:

```bash
export AWS_PROFILE=phishguard AWS_REGION=us-east-1

# 1. State bucket (once)
terraform -chdir=infra/bootstrap init
terraform -chdir=infra/bootstrap apply
terraform -chdir=infra/bootstrap output -raw backend_config > infra/backend.hcl

# 2. Everything else
cp infra/terraform.tfvars.example infra/terraform.tfvars   # set budget_email
terraform -chdir=infra init -backend-config=backend.hcl
terraform -chdir=infra plan -out=tfplan
terraform -chdir=infra apply tfplan
```

`backend.hcl`, `terraform.tfvars`, `tfplan` and the bootstrap's local state are git-ignored.

**First use of a model:** the first call to an Anthropic model on Bedrock subscribes the account through AWS Marketplace, which needs `aws-marketplace` permissions that the role and the group deliberately lack. An admin has already called Haiku 4.5 and Opus 4.6 on this account (`aws bedrock get-foundation-model-availability` shows them `AUTHORIZED`). If you add a model to `bedrock_inference_profiles`, invoke it once as an admin first.

## Verify

```bash
AWS_PROFILE=phishguard AWS_REGION=us-east-1 uv run python infra/verify_permissions.py
```

It asks the IAM policy simulator 20 questions about the agent role and a developer: the two Claude models are allowed through their profiles, a developer can use `aws login`, and any other model, direct model access without a profile, S3, creating users or access keys, changing someone else's password and signing in as the role are denied. Nothing is invoked, so it costs nothing.

## Give a teammate access

Terraform creates the users without passwords, so no password ever lands in the state. For each one:

1. IAM console → Users → `ale` → Security credentials → **Enable console access**, autogenerated password, **must create a new password at next sign-in**. Share it in person or through a password manager, not in chat.
2. The teammate signs in at `https://<account-id>.signin.aws.amazon.com/console`, sets a new password and adds an MFA device (Security credentials → Assign MFA device).
3. On their laptop: `aws login --profile phishguard --region us-east-1`, then the steps in the main README.

## Compute: run the agent on EC2

`compute/` is a separate stack with its own state, so destroying it leaves the IAM and the budget above alone. It creates:

| Resource | Purpose |
| --- | --- |
| `m7i-flex.large` instance (Amazon Linux 2023, 2 vCPU, 8 GiB plus 4 GB of swap) | One of the types an AWS Free plan account can launch; on a paid plan, `-var instance_type=m7i.xlarge` is faster. Runs the agent and Decider 2B on CPU, with the `agent-phish-guard-agent` instance profile. Credentials come from the instance role over IMDSv2 (required); there are no keys. Decider is a systemd service on 127.0.0.1, run by a dedicated `phishguard` user. Encrypted gp3 disk, deleted with the instance. |
| Security group | No inbound rules at all (no SSH, no open ports). Outbound HTTPS only. |
| Source bucket | Private, encrypted, HTTPS only. Holds the committed code packaged with `git archive`, so `.env` and `*.tfvars` never leave the laptop. Emptied and deleted by destroy. |
| Role additions | `AmazonSSMManagedInstanceCore` (Session Manager instead of SSH) and read access to the one source object. Both are attached to the agent role by this stack and removed by its destroy. |

Cost: about $0.10 an hour for the instance, plus a few cents of disk and Bedrock calls. Safety net: the instance terminates itself 3 hours after boot (`auto_terminate_minutes`), even if nobody runs destroy.

Speed, measured on 2026-10-22:
- **First boot:** about 3 minutes until Decider answers.
- **Per chunk:** on the `m7i-flex.large` (Intel Xeon Platinum 8488C, 2 vCPU), Decider takes about **9.3 s** to answer one chunk (the three scanner questions). That's against 0.62 s on an Apple M3 ([docs/benchmarks.md](../docs/benchmarks.md)), so scanning a page of about 20 chunks takes about 3 minutes.
- **What that means:** it's enough to show the agent and both guardrails running on AWS. Record the video on a laptop.

```bash
# 1. Package the committed code (tracked files only)
mkdir -p infra/compute/build
git archive --format=tar.gz -o infra/compute/build/source.tar.gz HEAD

# 2. Create it. The first boot installs PyTorch and downloads the model.
terraform -chdir=infra/compute init -backend-config=../backend.hcl -backend-config=key=infra/compute.tfstate
terraform -chdir=infra/compute apply

# 3. Run commands there through SSM (run.sh sends the command and waits for the output)
infra/compute/run.sh 'test -f READY && echo ready'
infra/compute/run.sh 'cd app && ~/.local/bin/uv run --env-file .env python -m agent.demo --guard full --warm --no-save | tail -40'

# 4. Destroy, then check nothing is left (both lists should be empty)
terraform -chdir=infra/compute destroy
aws ec2 describe-instances --filters Name=tag:Stack,Values=compute \
  Name=instance-state-name,Values=pending,running,stopping,stopped --query "Reservations[].Instances[].InstanceId"
aws s3api list-buckets --query "Buckets[?starts_with(Name, 'agent-phish-guard-source-')].Name"
```

## Tear down (after the hackathon)

```bash
terraform -chdir=infra/compute destroy     # if the compute is up
terraform -chdir=infra destroy
terraform -chdir=infra/bootstrap destroy   # last: it holds the state of the step above
```

Then delete the `stephy` user and `phishguard-admins` group by hand if the account will not be used again.
